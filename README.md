# Mini NPU Simulator

## 실행 방법
```
python main.py
```
- `1` 입력: 3×3 필터 A, B와 패턴을 한 줄씩(공백 구분) 직접 입력
- `2` 입력: `main.py`와 같은 폴더의 `data.json`을 읽어 일괄 판정
- Python 3.8+, 표준 라이브러리(json, time, re, os)만 사용

## 구현 요약
- **MAC 연산** (`mac`): 이중 반복문으로 같은 위치의 값을 곱해 누적 합을 반환한다. NumPy 미사용.
- **라벨 정규화** (`normalize_label`): `'+'`, `'cross'` → `Cross`, `'x'` → `X`. expected 값과 필터 키 모두 이 함수를 거친 뒤 비교하므로 표기 차이로 인한 FAIL이 생기지 않는다.
- **동점 정책** (`judge`): `abs(a - b) < 1e-9` 이면 `UNDECIDED`, 아니면 큰 쪽을 판정.
- **스키마 검증**: 키에서 `size_(N)_idx`로 N을 추출해 `size_N` 필터를 선택하고, 패턴이 N×N인지 확인한다. 키 형식 오류 / 필터 없음 / 라벨 미상 / 크기 불일치는 모두 해당 케이스만 FAIL 처리하고 다음 케이스로 진행한다.
- **입력 검증**: 모드 1에서 열 개수 불일치나 숫자 파싱 실패 시 안내 문구 출력 후 해당 행렬을 다시 입력받는다.
- **성능 측정** (`measure_ms`): `time.perf_counter`로 MAC 함수 호출 구간만 10회 반복 측정해 평균(ms)을 낸다. 측정용 입력은 모드 1에서는 사용자가 입력한 패턴·필터, 모드 2에서는 3×3 기본 패턴과 data.json의 5×5/13×13/25×25 필터를 사용한다.

|---|---|---|---|---|---|

| size_5_2 | 8.9 | 0.1 | Cross | Cross | PASS |
| size_13_1 | 0.3 | 14.700000000000008 | X | X | PASS |

총 6개 / 통과 3개 / 실패 3개

### 실패 원인 분석
1. **데이터/스키마 문제가 아니다.** 라벨은 정규화(`x`→X, `+`→Cross)로 모두 정상 해석됐고, 6개 케이스 모두 필터와 크기가 일치했다.
2. **로직 문제도 아니다.** 손으로 계산해도 세 케이스의 두 점수는 수학적으로 정확히 같다.
   - size_5_1: Cross 필터 중앙값 0.9 × 1 = 0.9, X 필터 0.1 × 9칸 = 0.9
   - size_13_2: Cross 필터 0.3 × 25칸 = 7.5, X 필터 중앙값 7.5 × 1 = 7.5
   - size_25_1: Cross 필터 중앙값 4.9 × 1 = 4.9, X 필터 0.1 × 49칸 = 4.9
   즉 data.json의 필터 가중치가 일부러 "동점"이 나오도록 설계되어 있다.
3. **수치 비교 문제(부동소수점)가 핵심이다.** 0.1, 0.3 같은 값은 2진수로 정확히 표현되지 않아 여러 번 더하면 0.8999999999999999처럼 아주 작은 오차(1e-16 ~ 1e-15)가 남는다.

### 시간 복잡도 분석
| 크기 | 평균 시간(ms) | 연산 횟수(N²) |
|---|---|---|
| 3×3 | 0.0009 | 9 |
| 5×5 | 0.0016 | 25 |
| 13×13 | 0.0075 | 169 |
| 25×25 | 0.0249 | 625 |

(측정값은 실행 환경마다 다르다.)

- MAC 연산은 N×N 칸을 한 번씩 방문해 곱셈 1회 + 덧셈 1회를 하므로 연산 횟수가 정확히 N²이고, 시간 복잡도는 **O(N²)** 이다.
- 13×13 → 25×25에서 연산 횟수는 625/169 ≈ 3.7배, 측정 시간은 0.0249/0.0075 ≈ 3.3배로 거의 비례한다.
- 3×3처럼 작은 크기에서는 함수 호출·반복문 준비 같은 고정 비용이 차지하는 비율이 커서 N² 비율보다 덜 증가해 보인다. N이 커질수록 N² 항이 지배적이 되어 비례 관계가 뚜렷해진다.
- 실제 NPU는 이 N²개의 곱셈을 병렬 MAC 유닛으로 동시에 처리해 이 시간을 크게 줄인다.
